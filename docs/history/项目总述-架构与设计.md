# 架构与设计（工程整理版）

> 本文为 2026-10-25 整理的脱离个人数据的新开发资料副本。删去原文中的私人经历、聊天摘录、模型回答和证据附件，保留工程目标、机制、结论及未完成状态。原报告中的测试/部署叙述不是本包的新验收证明。

## 路线与组件分层

产品 v1 选择 8788 事件层追加方法、稳定层检索归纳原则和当前独立检索。旧工作台用于复用聊天/传输/事件/隔离接缝，旧 v2.6维护不作为新生成算法。

| 层次 | 职责 | 工程边界 |
|---|---|---|
| 原始证据 | 用户消息、助手上下文、选中分支、源ID与时间 | 原件只读；新用户自有数据，本包无正文 |
| 常驻记忆 | 稳定背景+事件演变全文 | 来源支持与时间适用性需校验，不能摘要互证 |
| 当前会话 | 同conversation_id近期消息 | 40是消息条数；近期预算不代表记忆可截断 |
| 主模型 | 理解当前意图、委派缺口、结合证据回复 | 独立profile；不直接声称已写记忆 |
| 检索Agent | 自选查询→search/read/expand→JSON综合 | 只读now之前，排除当前消息；不写最终用户回答 |
| 摘要任务 | 初始化/增量/稳定层刷新→验证→发布 | 统一v1任务/HTTP尚缺，旧summary开关不能替代 |
| 前端事件 | 真实增量、工具交接、保存/失败/完成 | 重连不重发；草稿可被重置，最终保存文本为准 |
| 持久化 | 数据域、来源、版本、任务、请求/账本 | 单文件replace≠跨文件/DB原子；幂等≠失败重试 |

## 主聊天请求

服务端构造统一 Responses input：system含完整记忆、唯一now、当前会话近期；user是当前消息。后端维护消息角色，HTTP不接受任意system/messages/tool结果。工具轮使用原生function_call/function_call_output与call_id，保留协议必需reasoning items，不将XML/DSML文本当执行请求或最终答案。

主聊天和检索客户端显式分别传入，防止检索默认回落到主客户端；摘要也有独立profile和预算。无效finish/截断/空输出应失败或按有界恢复处理，坏助手回答不提交。

## 检索与证据

检索读取导入messages与绑定instance的chat_log，按selected branch、非reasoning、时间和当前消息排除筛选。词法相关性、别名扩写、读正文与邻居展开互补；snippet不是全文，has_more不是已翻页。

findings分user_fact/assistant_context/inference/state；message_at与event_at分别表达，plan不能推为completed。证据ID由本地验证并从原文物化，仍需确认支持具体措辞。trace的证据预算与交给主模型的handoff预算不同，前端保留truncated标志。

## 存储和导入

导出沿current_node父链保留选中分支，按tz-aware as-of截止；附件引用和缺时间单列。独立导入库经可信外部预期SHA绑定，核对规模与全字段冲突，成功数据+metadata同事务，失败另记，重导同源幂等。

长期用户域与短期会话分离，新会话不新建用户。coverage表示被处理的源范围，不能表示所有内容已保留；原文可检索与摘要已覆盖单独展示。旧v26发布marker只可作为历史设计参考。

## 8788 与旧维护的边界

事件层实际依赖letta-prototype worker/agents/ideastore；稳定层脚本依赖generated-memory-demo检索与context。目录名含Letta不代表主流程是Letta原生。8789原生对照、8787早期原型、8788固定两层及8791旧工作台数据必须隔离。

8788线上后台关闭、稳定层候选无定期失效与跨层整合。旧worker的任务marker、进程内锁、版本文件replace都不能证明严格exactly-once、跨进程安全或跨文件DB事务。新封装要显式修复这些缺口，不能悄改历史文档为“已具备”。

## 前端与部署目标

新包默认8794；8791仅历史地址。现有loopback工作台没有远程登录/多用户鉴权，也不支持跨源CORS；独立前端应选择同源/受控代理接入，不能假设换端口可直接调用。

iCloud只同步允许的数据和版本，不执行Agent；Mac/iPhone本地调度与供应商推理分开。跨设备冲突、后台执行与离线恢复属于后续实现。不要运行旧脚本去重建私人样本或直接同步活跃数据库。
