# 项目目标与开发边界（工程整理版）

> 本文为 2026-10-25 整理的脱离个人数据的新开发资料副本。删去原文中的私人经历、聊天摘录、模型回答和证据附件，保留工程目标、机制、结论及未完成状态。原报告中的测试/部署叙述不是本包的新验收证明。

## 正式方向

目标是 Mac/iPhone 上有长期记忆、尊重纠正、理解重要经历与变化的自然聊天工具；重点是记忆能力与连续理解，不拟合某个 GPT 的语言风格。2026-10-23 最新决定采用 **8788 摘要生成方法与原则 + 当前独立检索 Agent** 为产品 v1，v65/v66 与旧结构化维护不再作为后续默认路线。

本轮历史决策仅定版方法、文档、接口和参考源码，demo 保持原状。当前新包默认本地端口 8794；这不是将旧 8791 服务改名为已完成的 v1 writer。见[正式入口](../v1/README.md)。

## 记忆质量目标

- 充分保留有依据的背景、重要人物和经历、兴趣、明确偏好、近期重要变化。低频重要经历不能因词频低而丢失，临时高频话题不应支配长期理解。
- 历史、当前状态、一次例外、纠正和撤回都有适用范围；新信息可修正当前理解，同时保留历史。
- 用户自述、助手解释、计划、执行结果和模型推断分开。原话能找到还需支持具体措辞。
- 日常分享、倾诉、讨论和深入请求分别理解；记忆可以帮助理解而无需每条回答展示回顾、建议或追问。
- 旧摘要只作参考，不是事实 gold；持续整合最终需要从原始证据与可修订材料生成下一版，并维护失效、来源、差异和回滚。
- 完整上下文优先，不为节约 token 静默丢重要信息。稳定层/事件层是当前方法形态，长期容量和归档尚未解决。

## 通用性与时间

通用规则不硬编码某个用户、测试人物、地名、目标答案或专属偏好。个性化内容从用户自己的交流形成；读取更多历史不等于模型权重学习或微调。

区分 message_at、event_at、记录/更新时刻、适用区间和本轮真实 now。相对时间锚定原消息；模糊信息保留模糊；过期计划不是完成。事实强度、来源角色、当前适用性和话题相关性应有依据，尚未确定统一权重公式。

## 最终产品架构

```text
Mac / iPhone 本地数据与界面
  → 本地组装 now、完整记忆、当前会话近期消息
  → 本地调度主聊、检索、后台整理
  → 模型服务端推理
  → 本地保存对话、记忆版本与来源
  ↔ iCloud 仅承担允许同步的数据和版本
```

iCloud 不执行 Agent，不应默认依赖常在线 Mac 为 iPhone 代跑。SwiftUI 是长期倾向，现网页是验证工具。跨设备冲突、离线发送、iOS 后台/中断续作、凭据管理及 CloudKit/iCloud Drive 方案仍待设计，不能直接同步活跃 SQLite 或 Git worktree就宣称一致性完成。

保留自写路线与已认可检索，Letta 仅作机制借鉴/对照，没有决定迁移框架。主聊/检索/摘要各自配置模型，实际调用身份可观察，不把开发 agent 的模型偏好当永久产品限制。

## 验收与协作

工程接线、事实支持、状态更新、时间无泄漏、不同/相反偏好、日常与深入体验分别判断。比较摘要固定模型/提示/可见证据，固定回放与真实端到端分别报告。Agent 评分、关键词包含和组件测试不能代替事实审阅或真实体验。

已曝光例只作回归，不重新叫未见；冻结规则后再用独立材料。先过事实/更新门槛再作聊天对照，重要反例保留，失败不清账、不删旧结果求通过。

原始导出只读，demo/实验用户域隔离，凭据不入工程；后续只做必要核心验证。旧暂停/恢复、峰价偏好及单批订阅替代是当时执行记录，不成为新包自动调用模型的授权。本次仅资料整理，不执行模型 API。
