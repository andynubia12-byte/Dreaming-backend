# 需求与进度（工程整理版）

> 本文为 2026-10-25 整理的脱离个人数据的新开发资料副本。删去原文中的私人经历、聊天摘录、模型回答和证据附件，保留工程目标、机制、结论及未完成状态。原报告中的测试/部署叙述不是本包的新验收证明。

## 当前需求与交付界面

产品 v1 采用 8788 摘要方法/原则 + 当前独立记忆检索。希望主模型开口前已有充分背景理解，需要细节时检索原文，随后新增交流能在可靠更新后进入下一版记忆。当前文档和现有接口不代表统一写入能力完成。

最终是 Mac/iPhone 本地聊天工具与 iCloud 数据同步；网页 demo 是中间验证形态。早期“先记忆系统+简易demo”的阶段目标和后续重做前端应区分；旧 demo 保持原状，新包默认 8794。

## 功能需求与现状

| 需求 | 可复用部分 | 尚需明确/实现 |
|---|---|---|
| 详细常驻理解 | 两层完整文本组装、Published适配 | 新用户自己的摘要生成与有效性管理 |
| 原文检索 | 独立Agent、词法排序、读/展开、分类与来源物化 | 原文导入和数据域绑定；泛化质量仍需证据 |
| 连续聊天 | conversation_id、近期范围、幂等request_id、保存最终回答 | 原生UI、离线发送/恢复、跨设备接续 |
| 新会话 | 同workspace长期记忆与用量保留，近期隔离 | 不因切会话误清记忆或换用户域 |
| 真实流式 | run事件、增量/重置、检索交接、最终答案与运行终态 | 前端按实际phase处理，断线只重连 |
| 模型配置 | 统一Responses、三角色独立profile、显式effort、连接测试和发现 | 每厂商支持以真实错误为准，不静默降级 |
| 后台记忆 | 旧服务有v2.6维护可观测性 | 产品v1的8788 writer尚未封装，必须关闭旧summary |
| 导入与覆盖 | selected branch/as-of/角色，可信源hash、事务/冲突；coverage概念 | 无私人数据附带；新v1版本协议不能照搬旧v26 marker |
| 版本与恢复 | 历史版本/任务/请求记录的设计经验 | 跨层原子发布、多进程、可靠取消/重试、长期容量 |
| iCloud | 仅目标与设计边界 | 同步冲突、账号、凭据、iOS后台均未完成 |

## 已废止或被覆盖的需求解释

- 不再把 v65/v66 作为后续默认生成路线，不以旧 v2.6后台开关代表产品 v1。
- 记忆不是越短越好，不把实验16k字符上限、固定七类栏目或词频权重升级为产品规则。
- 不把助手旧回答当用户事实/gold，不以模仿GPT风格作为记忆能力验收。
- 原工作台双协议、临时Key仅进程内、维护只限旧CC的说明已经被后续统一Responses与Keychain覆盖。
- 安装成功、mock通过、搜索命中、来源可解析、版本升高、任务完成都不能替代具体语义正确与用户体验。

## 历史迭代要求

时间切分先于输入生成，测试时点只见之前材料；测试问题不能预先出现在摘要。工程控制、有限真实闭环、独立语义与部署分别报告。已曝光题作回归，不反复调到通过再叫泛化；判据变更有时点与原因，不回改旧结果。

前端对“回答已保存”“旧维护运行中”“记忆版本确实改变”“运行结束”分别展示。原始推理与凭据不进入UI；工具参数/证据/wire即使脱敏仍可能含用户原文，不能默认为公开资料。
