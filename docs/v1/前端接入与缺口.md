# 新前端接入与未完成能力

2026-10-25：统一 v1 摘要写入接口已补齐。历史方法资料与旧实验报告保持原有日期，当前实现以本页、[摘要写入 API](interfaces/摘要写入API.md)和 [OpenAPI](interfaces/openapi-existing.json)为准。

## 可直接接入的流程

默认本地地址 `http://127.0.0.1:8794`；手动启动 `scripts/start-local.sh`。本次只修改新项目，不切换原 demo。

```text
GET /workbench/bootstrap
  → 选择主聊、检索、摘要的独立 profile
POST /workbench/sessions
  → summary.engine=v1，memory.mode=none
  → session.id / session.workspace_id
POST /workbench/sessions/{sid}/memory/v1/jobs
  → initialize / append / refresh_stable
  → run_id → 订阅 /workbench/runs/{run_id}/events
GET /workbench/sessions/{sid}/memory/v1
  → 完整事件层 + 稳定层 + 组合全文与版本
POST /workbench/sessions/{sid}/chat
  → 注入当前版本 → 可独立调用检索 → 流式回复
  → summary.enabled=true 时追加本轮用户来源
```

没有个人历史或摘要随项目一起提供。初始化只读取该 workspace 绑定的原文；如需自己的数据，先明确导入再创建 workspace。生成方法与检索方法不能代替数据本身。

`memory.enabled` 决定是否注入，`retrieval.enabled` 决定是否向主模型提供检索工具，`summary.enabled` 决定是否自动增长；三者独立。`engine=v1` 是生成方法选择。后台更新关闭仍能读/注入已有版本，也能显式发整理任务。

`continue_from` 创建新的短期会话但共享 workspace 的长期记忆。普通新建 workspace 则隔离。变更长期记忆来源、引擎、摘要 profile 或累计预算应新建 workspace，不能借切换主模型改变它们。

## 前端要区分的结果

| 信号 | 含义 |
|---|---|
| 202 + run_id | 任务已受理，尚未生成成功 |
| answer_delta / draft_reset | 回答草稿增量及清空草稿 |
| tool/retrieval 事件 | 实际工具请求、返回与交接；有调用不等于有命中 |
| answer_complete | 已保存聊天回答，不表示记忆已更新 |
| 摘要任务阶段、工具事件 | 展示整理步骤和实际数据；不要把工具 JSON 当回答 |
| published + 新版本 | 记忆已原子发布，可读取完整两层 |
| noop | 没有新增持久内容；不能显示成新版本发布 |
| failed / interrupted | 失败或进程中断；读取 run 错误及当前版本再决定是否重提 |
| run_complete | 当前任务终态，仍需核对 status/result |
| 409 | workspace 忙、版本冲突或请求 ID 冲突；先刷新状态，不能自动覆写 |

SSE 用 seq 游标重连；终态后关闭连接。重复提交相同 request_id 是取回同一次任务，不是重试。服务重启不自动重发收费请求。新的重试由客户端显式使用新 UUID 与当前版本，保留旧 run 记录。

聊天答案与摘要结果分别保存，摘要失败不删除答案。读取 wire 仍可能包含用户上下文和工具证据，不能因凭据/思考已脱敏就当成公开日志。

## 本轮没有扩展的能力

- 稳定层定时刷新、跨层语义冲突自动消解、无限历史自动分批调度；稳定层当前是显式任务。
- 人工任意改写摘要、版本回滚、HTTP 取消及自动失败重试。
- 当前旧批量实验的 v1 后维护。v1 引擎请求必须明确拒绝，不能悄悄跑旧 v2.6。
- Mac/iPhone 新前端、多用户远程鉴权、iCloud 同步及跨设备版本合并。
- 真实供应商生成质量。离线合成验证只说明请求、工具、事务与接线的工程行为，不证明模型能正确理解所有真实故事。
