# 运行与前端接入

此包提供当前 continuity-trial-v2 的 Python 后端、现有前端、CLI，以及其实际引用的旧 v2.6 维护引擎依赖。数据从空白开始；后续新前端可对接下列现有接口。

**版本边界：旧 v2.6 维护引擎及 citation-alias wire 仅为兼容现有功能保留，不属于 v1 选定摘要方法。新包已提供显式 v1 初始化/追加/稳定层刷新接口；没有改写原 8788 服务，也没有验证真实供应商输出质量。**

## 启动

开发建议 Python 3.11 或以上；源码语法/API 下限为 3.10（未逐版本验证），本次实际使用 Python 3.14.6。运行代码仅依赖 Python 标准库，包括 sqlite3；不需要 pip、Node、npm、Letta 服务或旧项目虚拟环境。保存新 API Key 到钥匙串的现有功能仅支持 macOS。

```sh
cd /Users/andy/Projects/Dreaming-backend
./scripts/start-local.sh
```

默认启动当前工作台，地址 http://127.0.0.1:8794/，只监听本机。Ctrl+C 停止。不会自动装依赖、导入历史、读取用户旧模型池或发送供应商请求。

原计划使用的 8792 被已有 node 进程占用，因此本包改为 8794；未停止或修改原进程。需要时可显式另选端口：

```sh
./scripts/start-local.sh --port 8795
```

保留旧持续记忆试用 API/页面入口，需另行选择模式；两个模式使用相同默认端口，应择一启动，或显式使用不同端口：

```sh
./scripts/start-local.sh --trial --port 8794
# 只查看旧 API、不启动维护线程：
./scripts/start-local.sh --trial --port 8794 --no-worker
```

也保留 work/continuity-trial-v2 下的 start.py、start_workbench.py、start.sh、start_workbench.sh、import_history.py、eval.py，以及 src/continuity/sandbox_summary_cli.py。全部启动包装器均已移除旧 credential wrapper；维护 CLI 位于 work/memory-maintenance-v1/review-v2/run_update_with_citation_alias.py。

## 新前端优先使用工作台接口

工作台模式与旧试用模式是两套现有 API，不能混用 URL。工作台入口在 src/continuity/workbench.py，浏览器参考实现为同目录 workbench.html、workbench.js、workbench.css。

| 方法与路径 | 行为 |
| --- | --- |
| GET /workbench/bootstrap | 模型、可用记忆、会话、批次、默认值与能力 |
| GET /workbench/models | 模型池与凭据可用状态，不触发模型连接测试 |
| POST /workbench/models | 保存模型配置；参数见既有前端 |
| DELETE /workbench/models/{id} | 删除模型池条目 |
| POST /workbench/models/test | 显式供应商连接测试，会发送请求 |
| POST /workbench/models/discover | 显式获取供应商模型列表，会访问网络 |
| POST /workbench/sessions | 创建独立实验会话，返回 session.id |
| GET /workbench/sessions/{sid} | 会话详情与消息 |
| POST /workbench/sessions/{sid}/rename | 修改标题，JSON 为 {"title":"新标题"} |
| DELETE /workbench/sessions/{sid} | 删除会话；共享 workspace 的保留语义见 session_management.py |
| GET /workbench/sessions/{sid}/memory | 该实验当前已发布记忆 |
| POST /workbench/sessions/{sid}/chat | 启动回答，返回 run_id；会调用所选模型 |
| GET /workbench/runs/{rid} | 运行状态 |
| GET /workbench/runs/{rid}/events | SSE 事件，支持 Last-Event-ID 或 ?after=整数 |
| GET /workbench/runs/{rid}/wire | 脱敏请求记录；artifacts 路径也可用 |
| POST /workbench/batches/plan | 规划批量实验，不执行供应商模型调用 |
| POST /workbench/batches | 开始批次，会调用模型 |
| POST /workbench/batches/{bid}/resume | 恢复批次 |
| GET /workbench/batches/{bid} | 批次状态和结果 |
| GET /workbench/batches/{bid}/report | 批次 HTML 报告 |
| GET /workbench/batches/{bid}/results/{cid} | 单条实验结果和脱敏记录 |

创建空记忆、关闭检索与后台摘要的会话，可从 bootstrap.profiles 取一个所选模型作为 model，再发送：

```js
const boot = await fetch('/workbench/bootstrap').then(r => r.json());
const created = await fetch('/workbench/sessions', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    model: boot.profiles[0], memory: {mode: 'none'},
    retrieval: {enabled: false}, summary: {enabled: false}, title: '新实验'
  })
}).then(r => r.json());
// 发送消息时，向 /workbench/sessions/{created.session.id}/chat 提交：
// {request_id: crypto.randomUUID(), message: '你的消息'}
// 该步骤会调用模型；本次打包未执行。
```

同一消息重试复用原 request_id，避免重复运行。订阅 run_id 的 SSE，按事件 seq 更新游标；phase=run_complete 后关闭连接；reset 事件表示需按 reset_after 重置游标。回答结束后后台摘要可能仍在运行，应继续跟踪整次 run 状态。显式 summary.engine=v1 时使用新写入链路；缺省旧请求仍使用旧 v2.6。

服务验证 Host、Origin 和 Sec-Fetch-Site，未开放任意跨域。新前端应与 API 同源；本地开发使用受信本机代理时需使转发的 Host/Origin 与后端地址匹配，不能只在浏览器中改一个跨域 base URL。

## 旧试用 API

--trial 模式的 src/continuity/api.py 提供 GET /health、/memory、/status、/sessions、/history?conversation_id=…、/events，以及 POST /chat、/chat/stream、/search、/retry。聊天 JSON 使用 message、conversation_id；流式请求另需 request_id，直接返回 SSE。/retry 使用 task_id。该模式成功回答会进入串行维护队列（除非 --no-worker），与工作台按 workspace 隔离的实验状态不同。
